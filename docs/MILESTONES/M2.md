# M2: Storage and Secrets

- Date: 2026-10-26
- Status: implementation complete locally; exit criterion met; evidence recorded
- Governing design: `docs/DECISIONS/ADR-0002-storage-encryption.md` (G2 approved 2026-10-25)
- Milestone exit: encrypted persistence across restart proven by test

## Delivered

All production code is in `companion/packages/core/src/storage/` with tests beside it.

- SQLCipher-compatible encrypted database opened with a random 32-byte database key. The key is wrapped by Electron async `safeStorage` (DPAPI) and described by a pinned manifest (`db-key.json`); the wrapped blob is `db-key.bin`. Cipher settings are asserted on every open: `sqlcipher`, page size 4096, PBKDF2-HMAC-SHA512 256,000 iterations, WAL, `synchronous=FULL`, foreign keys on, `temp_store=MEMORY`, and `cipher_memory_security=ON` when available.
- Versioned migrations with SHA-256 checksums, transactional up/down, `user_version` consistency checks, and a pre-migration `VACUUM INTO` snapshot. The initial schema contains `settings`, `conversations`, `messages`, `memories`, `audit_log`, `schema_migrations`, FTS5 indexes for messages and memories, and sync triggers.
- Windows Credential Manager adapter over `@github/keytar`: service `Companion`, account `provider/<providerId>`, typed errors, no plaintext fallback. Provider keys are never written to SQLite, config, logs, exports, or backups.
- Encrypted local snapshots via `VACUUM INTO` (the package's `backup()` API is unusable with encrypted source/target in 13.0.3).
- Portable owner recovery using format `COMPORT1`: scrypt N=131072, r=8, p=1 with a random 16-byte salt; AES-256-GCM with a random 12-byte nonce and authenticated header; 12-1,024 character passphrase. The database key is inside the encrypted envelope only. Restore decrypts to staging, verifies and migrates the database, rekeys it to a fresh local key and DPAPI wrapping, keeps a pre-restore snapshot and key-file copy, and rolls back on failure.
- Desktop wiring: the main process opens the encrypted database at startup, logs to `%APPDATA%\Companion\logs\companion.log`, closes it before quit, and performs a read-only Credential Manager availability check. The application name is set to `Companion` so user data is not stored under the npm package path.

## Verification

- `npm run verify` from `companion/`: ESLint clean, TypeScript clean, 5 test files / 28 tests passed, desktop build completed (main bundle 779.8 KB).
- New storage tests: 19 across `database.test.ts`, `backup.test.ts` and `credentials.test.ts`. They cover pinned cipher parameters, reopen/restart, key rewrap, missing/wrong key, unavailable protector, migration up/down/rollback/checksum mismatch, FTS5 trigger sync, snapshots, portable export/restore/rekey, wrong passphrase, ciphertext tamper, raw-key/plaintext scans, and the keytar adapter with a fake Credential Manager.
- First test run after adding file logging hit the default 5,000 ms test timeout on the scrypt round-trip (5,280 ms). The test harness timeout is now 30,000 ms; the security parameters were not reduced.
- Packaged app `apps/desktop/release/win-unpacked/Companion.exe` was launched four times. Every launch logged `encrypted storage opened` with the same key id (`e2494286-de47-4fda-a50d-ea95084b5310`) and schema version 1; the last two launches also logged `credential store available` with `providerCount: 0`.
- The live profile at `%APPDATA%\Companion` contains `data/companion.db` (106,496 bytes), `keys/db-key.bin` (91 bytes) and `keys/db-key.json`; the database header is not the plaintext `SQLite format 3` header, and the manifest pins cipher `sqlcipher`, page size 4096 and KDF iterations 256,000 with `electron-safe-storage` wrapping.
- Final unsigned NSIS installer: 122,591,732 bytes (116.9 MiB), SHA256 `601DDDF417C36823F38EDBB2A5E84D2CE9F668888E071F90D0EE73EC1590D06B`, Authenticode `NotSigned`; unpacked app 379,181,612 bytes across 103 files. Only the win32-x64 keytar and SQLite `.node` files are unpacked.
- Secret checks: the automated storage scan found no database key text, message marker, plaintext database header, or key material in the profile, logs, snapshots, or portable export; a `git grep` review found only test doubles and token/identifier names, no live credentials. There is no CI secret scan yet.

## Limits and follow-ups

- Storage and credential modules are not exposed over IPC or UI yet; backup status/restore UI belongs to M9, and the Setup Doctor will use these APIs in M3.
- The packaged app has exercised real DPAPI opening and real keytar enumeration. A real provider key write/read/delete through the production adapter has not run because no provider key exists; the G2 prototype exercised set/get/list/delete under Electron 45.
- The installer is unsigned, uses the default icon, and has not been installed on a clean machine. CI has not run on GitHub.
- The diagnostics log is plaintext JSON, unrotated, and must never receive private content or secrets. Log redaction covers sensitive key names, not free text.
- Backup retention/rotation and profile-deletion integration are not implemented.
- The pre-rename smoke profile at `%APPDATA%\@companion\desktop` remains as a local test artifact; it is not used by the current app.
- Scrypt adds noticeable cost to export and restore (roughly 1-5 seconds per operation on the test machine); progress UI is needed before exposing recovery to the owner.
