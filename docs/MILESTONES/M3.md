# Milestone M3: Onboarding Engine Core

**Status:** COMPLETE  
**Completed:** 2026-10-26

## Objective

Build the onboarding engine core: a persisted state machine over a registry of setup steps, with resumability after crashes, idempotency, and Setup Doctor repair mode. This engine becomes the product's backbone - every module registers its setup steps with it, and it can be re-run, repaired, and extended forever.

### 3. Onboarding Engine State Machine (commit c48e9fc)
**File:** `companion/packages/core/src/onboarding/engine.ts`

`DefaultOnboardingEngine` implements:
- **Idempotent execution**: Calls `detect()` before every `run()` to skip already-satisfied steps
- **Resumability**: Persists state after every transition; resumes from `currentStep` on restart
- **Setup Doctor mode**: `repair()` re-detects all completed steps and fixes broken ones
- **Cancellation**: Respects `AbortSignal` to stop mid-execution
- **Skip support**: Can skip optional steps without executing them
- **Failure handling**: Records failures with code/message, continues with non-required steps

**Tests (13 passing):**

- Stops on required step failure
- Continues past optional step failure

- Skips optional steps
- Throws error when skipping required step
- Repairs broken steps in Setup Doctor mode
- Respects cancellation signal
- Verifies steps after execution
- Runs rollback on failure
- Handles steps with no dependencies

### 4. Concrete Setup Steps (commit aa25fa2)
**Files:** 
- `companion/packages/core/src/onboarding/steps/system-check.ts`
- `companion/packages/core/src/onboarding/steps/preset-choice.ts`

**SystemCheckStep** (required, non-skippable):
- Verifies Windows platform (fails on non-Windows)
- Checks Windows version (minimum 10.0.19041 - Windows 10 20H1)
- Checks disk space (minimum 500 MB)
- Checks memory (minimum 512 MB, warning if low)
- No data sent anywhere (privacy-safe)

**PresetChoiceStep** (required, skippable with default):
- **Recommended**: Balanced memory with approval for inferences, reflection 10% quota, Class 3 confirmations
- **Privacy-first**: Approve all memories, reflection off, Class 2 & 3 confirmations, limit providers
- **Minimal**: Manual memory, reflection off, Class 3 confirmations only
- Choice affects memory, reflection, and confirmation behavior
- Defaults to "recommended" if skipped
- Can be changed later in Privacy Center

**Tests:** 9 system-check + 16 preset-choice = 25 tests passing

## Architecture

```
SetupStep (interface)
    ↓ implements
SystemCheckStep, PresetChoiceStep (concrete steps)
    ↓ registered in
DefaultStepRegistry (topological sort, cycle detection)
    ↓ consumed by
DefaultOnboardingEngine (state machine)
    ↓ persists via
DatabaseOnboardingStorage → encrypted database (M2)
```

**Resumability flow:**
1. Engine calls `storage.loadState()` on start
2. Finds `currentStep` from persisted state
3. Skips completed steps (via `detect()`)
4. Resumes execution at `currentStep`
5. Saves state after every step transition

**Idempotency mechanism:**
- Before running each step: `const detected = await step.detect(ctx)`
- If `detected.status === 'satisfied'`: skip to next step
- Only run if `notStarted` or `needsUser`
- Prevents duplicate work on retries/resumes
